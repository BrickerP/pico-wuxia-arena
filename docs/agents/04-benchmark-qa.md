## 验收与边界

- 快乐路径：一个人能进入、完成格挡或弹反并反击、结束战斗并重开；相同轨迹能复查预期结果。
- 边界至少覆盖：刀刃高速穿透、静止持刀误判弹反、一次挥刀重复命中、身体未避开却判成功、技能误触、追踪中断、暂停与重开。
- 区分三种证据：桌面可验战斗规则；模拟器可检查构建和基础流程；真实动作识别、舒适度、触觉、实机画质与性能必须在真机验证。Windows 构建未实际在 Windows 运行时不得声称 Windows 测试通过。
- PICO 4 以 72 Hz 为初始目标；30 分钟规则来自 [PICO Space Program 正式规则](https://spaceprogram-cn.picoxr.com/docs/pico-space-program-rules.pdf)。少量试玩只用于早期筛选，不冒充行业标准或市场结论。

### 固定场景与招式提案

以下是单人灰盒的可复现候选值。除明确标注输入时钟外，时间均为相对于开始游戏的**模拟时间**；暂停期间模拟时间不前进。坐标仅是 QA 夹具的局部参考：原点在玩家初始脚下，`+X` 为玩家右方、`+Y` 向上、`+Z` 朝敌人，单位米；接入时由主控确认的坐标契约一次性映射，不要求生产输入采用此坐标系。玩家初始头部 `(0, 1.60, 0)`，敌人根节点 `(0, 0, 1.50)`、面向玩家，避开战斗侧候选出招距离 `1.60 m` 的边界。所有样例从已校准、双方存活、无动作进行中的同一初始状态开始。

| 招式 | 固定调度 | 方向与用途 |
| --- | --- | --- |
| `E-L` | `1000 ms` 进入预备；预备 `550 ms`、出招 `180 ms`、生效 `200 ms`、恢复 `600 ms` | 从玩家左向右横斩；验证方向、时序、可防御和避让。 |
| `E-R` | 同 `E-L` | 从玩家右向左横斩；验证镜像方向，避免只测一侧。 |
| `E-O` | `1000 ms` 进入预备；预备 `650 ms`、出招 `250 ms`、生效 `200 ms`、恢复 `650 ms` | 从玩家上方向下斩；用于格挡、弹反及反击基准。 |
| `E-idle` | 测试期间不发起攻击 | 用于无来袭误报、技能误触及追踪中断。 |

以上时序对齐当前未提交的[战斗侧交接提案](01-combat.md)，不是已冻结玩法。候选接触点为横斩 `1800 ms`、上劈 `1960 ms`，各 `±20 ms`；战斗侧候选弹反条件为接触发生在生效开始后的 `[0, 120 ms)`，并且接触前 `100 ms` 内玩家刀刃朝敌刀主动移动的投影不少于 `0.08 m`，样本不足或起点已相交只算普通格挡。必须按真实武器/身体碰撞体校准，不能由测试脚本伪造接触或成功事件。测试只控制随机种子或敌人**正常决策入口**来选择招式，仍须经过敌人状态、动作、碰撞和战斗裁定；若尚无此接入点，记录为阻塞。测试中禁止额外招式干扰单招用例，但不得跳过正在执行的招式状态。

### 桌面虚拟轨迹提案

样例为输入观察时钟上的 `100 Hz`、每 `10 ms` 一个带时间戳采样，位置在关键帧之间线性插值，旋转使用归一化四元数的球面插值；每帧包含序号、输入源、校准坐标代次、头部及双手位姿，以及各部位**位置和方向分别的追踪有效性**。测试应按顺序交付每个已采样点；缓冲溢出时须显式报告缺口，不得静默合并、丢弃或跨缺口连接轨迹。未暂停时输入时钟与模拟时间同起点；暂停时输入时钟继续递增，测试仍须接收失效、恢复和重开信息，战斗模拟时间保持不变。应记录两时钟的映射，不能在暂停期间用冻结的模拟时间驱动恢复采样。

明确标注保持时不得提前向下一点插值；未再指定的部位保持上一关键帧。初始左手 `(-0.20, 1.25, 0.35)`、右手 `R0=(0.25, 1.25, 0.35)`，各部位初始旋转 `Q0=(0, 0, 0, 1)`，四元数顺序为 `(x, y, z, w)`。失效区间和恢复瞬间不跨区间插值；右手持刀，左手保持初始姿态，除非用例另有说明。

| 轨迹点 | 位置 `(x,y,z)` | 旋转 | 用途 |
| --- | --- | --- | --- |
| `G` | `(0.40, 1.40, 0.55)` | `(0, 0, 0.70710678, 0.70710678)` | 候选接刀/挥击起点。 |
| `M` | `(0.90, 1.40, 0.55)` | 同 `G` | 同时机偏离刀路的失手样例。 |
| `B` | `(-0.40, 1.40, 0.55)` | `(0, 0, -0.70710678, 0.70710678)` | 挥击终点。 |
| `C` | `(-0.10, 1.40, 0.55)` | 同 `B` | 候选挥击后持续重叠位置。 |
| `H-out` | 头部 `(0.50, 1.60, 0)` | `Q0` | 候选离开攻击范围。 |
| `H-in` | 头部 `(0.04, 1.60, 0)` | `Q0` | 身体仍在攻击范围内的对照。 |

具体键盘映射、持刀握点与刀身长度尚未确定，故这些点是**数字化提案而非已验证的碰撞轨迹**。冻结后须用实际刀身、角色受击体、头部代理和动作阈值独立核对：`G` 与目标攻击相交、`M` 与攻击路径至少留 `0.10 m` 间隙、`H-out` 移出攻击范围、`H-in` 仍在范围；高速挥击需有至少一对相邻采样均未重叠，而两点之间的扫掠体与目标相交。时机正例至少离有效窗口两端 `40 ms`。几何或窗口不满足时将样例标记为**夹具待校准**并重新审核，不得当作识别通过/失败，也不得只改预期来让测试通过。

回放在输入采样边界送入完整位姿，后续走桌面与 PICO 共用的动作和战斗规则，不能直接调用“命中/弹反/闪避成功”。此外必须从真实桌面入口注入或人工操作已确认的键盘动作，核对生成的连续轨迹确实进入同一条链路；仅做采样边界回放不能声称键盘到游戏的端到端已通过。主场景的进入、胜负及重开要通过实际 UI/控制入口核对，入口不存在时记为阻塞。

需要敌人受击目标的样例须在首帧通过夹具配置健康值和位置，但实际扣血必须由正常挥击触发。胜利用例允许死亡中断敌人恢复，不要求死亡后继续输出恢复事件；重开后再验证下一局状态。任何缺失的真实入口、碰撞体、动作阈值或可观测事件均记为**阻塞**，不把缺失事件当成通过。

- 原始证据记录：各部位采样时间、位姿和有效性；敌人招式/状态时间、挥击标识、刀刃及目标碰撞体、可独立复查的接触/距离、伤害前后血量、技能资源、暂停/恢复/重开、胜负及反馈事件时间。保留关联同一攻击/挥击的标识与事件顺序；不记录个人敏感信息。
- 每例单独写明**预设意图**、独立核实的几何/时机/追踪前置条件、预期、实际、通过/失败/阻塞及复现步骤。前置条件成立的有效动作未识别才是漏识别；时机过早、过晚、错位或追踪无效是无效尝试，未触发是正确结果，错误触发才是误报；前置条件无法确认则列阻塞，不计入识别率分母。
- 后续按动作类型及输入来源分别统计：有效动作识别率 = 正确识别的有效次数 / 前置条件成立的有效次数；误报率 = 错误触发的无效尝试次数 / 前置条件成立的无效尝试次数，同时记录样本数和失败原因。桌面合成样本不能作为真实 PICO 识别率。
