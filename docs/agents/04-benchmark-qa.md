## 项目与目标

项目仓库：`/Users/yupeng/projects/personal/pico-wuxia-arena`。

项目是 4–6 分钟中式 PVE VR 单挑 Demo，先验证 Windows/macOS 键盘模拟，再接入 PICO 4。战斗手感优先，其次是具有真实细节的中式画面。VR 的挥刀、格挡、弹反、闪避、技能和处决依靠动作识别；桌面虚拟轨迹和 PICO 真实轨迹共用战斗规则。

## 职责边界

- 负责 `Assets/Tests/Integration/`、必要的测试夹具和 `Tools/bench/`：跨模块自动化、固定轨迹与招式回放、指标定义和参赛验收。战斗和输入各自负责本模块单元测试。
- 主控负责共享输入契约、项目设置、包依赖和主场景；需要跨目录修改时在本文件提出，不直接改其他 Agent 的实现或进度文档。

## 首批任务

1. 立即确定固定敌人招式、桌面虚拟轨迹、测试对象和记录字段；区分“动作想做但时机错误”和“动作有效但识别错误”，在本文件交主控审核。
2. 基线建立后实现跨输入、战斗及场景的可重复测试：同一轨迹检查事件顺序、游戏结果和合理时间容差；不要要求不同平台的 Unity 物理逐帧完全一致。
3. 桌面版核对完整流程、手感相关事件和动画衔接；参考《Blade & Sorcery》《荣耀战魂》《Dragon Fist》《Battle Talent》安排真实对照试玩，但未实际试玩时只能写“待测”，不得杜撰比较数据。
4. 有 PICO 真机后记录设备型号、系统、构建、刷新率、帧时间、掉帧及温度状态；完整体验重复运行至少 30 分钟，检查崩溃、卡死、重开和主流程。按比赛规则准备对应安装包、GitHub commit 和素材验证。

## 验收与边界

- 快乐路径：一个人能进入、完成格挡或弹反并反击、结束战斗并重开；相同轨迹能复查预期结果。
- 边界至少覆盖：刀刃高速穿透、静止持刀误判弹反、一次挥刀重复命中、身体未避开却判成功、技能误触、追踪中断、暂停与重开。
- 区分三种证据：桌面可验战斗规则；模拟器可检查构建和基础流程；真实动作识别、舒适度、触觉、实机画质与性能必须在真机验证。Windows 构建未实际在 Windows 运行时不得声称 Windows 测试通过。
- PICO 4 以 72 Hz 为初始目标；30 分钟规则来自 [PICO Space Program 正式规则](https://spaceprogram-cn.picoxr.com/docs/pico-space-program-rules.pdf)。少量试玩只用于早期筛选，不冒充行业标准或市场结论。
