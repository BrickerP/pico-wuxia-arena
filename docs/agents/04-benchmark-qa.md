# 当前实现与后续验收交付

## 当前范围与职责

用户本轮要求先不自测、专注开发。主控负责唯一仓库的源码整合与必要编译，协作者按文件职责交付后结束。本文件定义后续验收条件，当前不执行设备操作、测试套件、日志轮询或等待循环。

## 上一轮产出

历史基线运行过84项单元测试，并留有角色、HUD及待机的静态画面。该记录对应上一轮版本，不能引用为本轮新增姿态判定、三轮流程、资源与结算的通过证据。

## 本轮 review 修正与交付

当前代码覆盖准备、倒计时、三轮交战、清场补给、胜利／死亡／超时结算和重新挑战。动作结果已从同一头手快照进入既有战斗状态机，新增玩家资源、连击、气势、破势及低血自动处决。

本轮review修正包括旋转扫掠中间刀段、静止架刀观察、接触时钟弹反、阶段／接触切段消费、技能与普通命中择一消费、原始坐姿hurt的表现适配，以及方向Badge纵深覆盖候选。音效与触觉按事件编号消费，场景补充同源前院铺地。

主控已报告功能版 `:app:assembleDebug --offline` 编译打包成功，本轮没有执行自测、单元测试或设备验收。主题收敛设计为revision14，设计receipt明确将旧revision10证据标为历史，当前验证延期。

主题review将接近步法、站立受击和处决收势列入完成条件。当前idle滑移与fall复用只支撑已有功能表现。评审同时核对实际刀术交互、中式近景、动作衔接和完整流程，分别记录各项结果。

## 迭代 benchmark 与方向判断

游戏项目的benchmark同时包含参考体验、技术基线和玩家行为。这里以Blade & Sorcery的手部动作与命中确定感、For Honor的读招和攻防节奏作为交互参照，以黑神话悟空、影之刃零的中式材质、空间层次和冷暖用光作为视觉参照。每轮围绕同一场地、同一把刀、同一刀客比较，固定构建和设备后再改变一个影响手感的参数。

下表是后续验收目标，本轮没有执行或产生测量结果。

| 维度 | 同条件比较方式与目标 |
| --- | --- |
| 完整流程 | 三轮胜利、生命归零、超时、暂停恢复、重开各实际完成3次，入口至结果无阻塞，重开无残留伤害或旧输入 |
| 动作确定性 | 同一玩家各做10次明确斩击、架刀和闪避，预期动作识别至少9次，同一挥击及同一敌招只消费一次，静止贴刀无追加伤害 |
| 攻防节奏 | 固定敌人阶段与生命，比较每轮格挡、弹反、闪避、受击和击杀时间，核对持续进攻、持续防御与反击三种策略都具备可读的收益和代价 |
| 主观手感 | 至少5名首次体验者分别评价命中确定感、读招清晰度、反馈和舒适度，5分制各项中位数达到4，至少4人愿意再玩一局 |
| 视觉 | 同机位比较近景角色、刀握点、脚下接触、材质和HUD，清除悬空、明显穿插、覆盖视线和主要文字裁切，再评估装饰细节 |
| 终端预算 | 以Space Pro实际显示刷新率f计算每帧预算1000/f毫秒，记录帧耗时分位数、掉帧、峰值内存与热稳定性，连续三局无崩溃或资源持续增长 |

方向判断优先看动作确定性、完整流程和重玩意愿。比较结果若只提高静态画面评分，命中或攻防理解评分下降，应回到动作时序、距离与反馈调参。新的场景、敌人和系统扩展应建立在当前短试炼达到上述目标之后。
