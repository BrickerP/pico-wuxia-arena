## 项目与目标

项目仓库：`/Users/yupeng/projects/personal/pico-wuxia-arena`。

制作 4–6 分钟的中式 PVE VR 单挑 Demo：一处雨夜山镇酒馆擂场、一把刀、一个敌人、一个技能和一次处决。战斗手感第一，视觉第二。参考《Blade & Sorcery》的刀剑接触和《荣耀战魂》的格挡、弹反、闪避、动作衔接与处决。先做 Windows/macOS 键盘模拟，再接入 PICO 4；真实 VR 战斗操作由头部与手部动作识别，不用战斗按键。

## 职责边界

- 负责 `Assets/Game/Combat/` 与 `Assets/Tests/EditMode/Combat/`：敌人 AI、战斗状态、攻击时序、刀刃接触、伤害与攻防结果、技能和处决；负责自己的单元测试。
- 战斗侧拥有敌人战斗 prefab 和 Animator Controller；美术侧提供模型、骨架、原始动作、刀具定位点和单体视觉 prefab。主控独占主场景、项目设置、包依赖与共享契约。
- 输入侧提供带时间戳的头部、双手轨迹及追踪有效性，并可提供实时挥刀段、技能动作候选；本侧结合敌人攻击、接触和时间裁定是否命中、格挡、弹反或躲开。不要在两侧各做一套攻防成功判定。
- 不修改其他 Agent 负责的目录或进度文档；不覆盖或回滚他人工作。不自行合入主分支或推送远端。

## 首批任务

1. 在本文件的“最新交接详情”中提出敌人待机、预备、出招、生效、恢复、受击和死亡的最小状态与时序；列出需要的三方向攻击和动作片段。准备工作可立即进行。
2. 主控建立 Unity 基线并确认共享输入契约后，在独立分支与工作副本中实现一对一桌面灰盒：三方向出招、挥刀、格挡、弹反、闪避、反击、胜负及重开。
3. 在闭环稳定后加入一个技能和一次处决。处决不能强制移动玩家头部或手部；动画画面和伤害生效必须使用一致的时序依据。
4. 接入美术资产和真实 PICO 追踪后，再调节敌人反应、碰撞反馈和时间窗口。桌面键盘不能直接调用“命中”“弹反成功”或无敌。

## 验收与边界

- 快乐路径：一次来袭攻击可被格挡或弹反，弹反后能反击，战斗可结束并重开。
- 边界至少覆盖：提前静止持刀只算普通格挡；错误时机不算弹反；快速挥刀不会跳过接触；一次挥击不会重复伤害；没有移出攻击范围不能凭闪避动作获得无敌；追踪丢失不能误判攻击或受伤。
- 保留可供 QA 重放的敌人招式与事件结果。跨平台物理不要求逐帧完全一致，要求结果和时间误差符合约定。
- 没有 PICO 真机时，不能声称真实 VR 识别、手感、舒适度或性能已经通过。
