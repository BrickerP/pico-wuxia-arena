## 项目与目标

项目仓库：`/Users/yupeng/projects/personal/pico-wuxia-arena`。

制作一段中式 PVE VR 单挑 Demo，先在 Windows/macOS 用键盘模拟，再适配 PICO 4。真实 VR 的挥刀、格挡、弹反、闪避、技能和处决依靠头部与手柄动作，不以战斗按键触发。桌面和 PICO 共用同一条动作与战斗判定路径。

## 职责边界

- 负责 `Assets/Game/Input/` 与 `Assets/Tests/EditMode/Input/`：键盘生成虚拟头手轨迹、PICO 头显和双手柄轨迹、追踪有效性、校准、重置和与战斗无关的动作候选；负责自己的单元测试。
- 主控拥有共享输入契约与坐标体系。输入层提供带时间戳、追踪状态和校准信息的头手采样；战斗侧结合敌人状态、刀刃接触、攻击范围与时机裁定格挡、弹反、闪避、伤害、技能生效和处决。
- 首版只在需要时提供实时挥刀段和技能手势候选；挥刀过程中即时提供轨迹及挥击标识，不得等动作结束才反馈。闪避成功由战斗系统依据头部轨迹和攻击范围裁定。
- 不修改战斗、美术、主场景、项目设置、依赖和其他 Agent 的进度文档；不覆盖或回滚他人工作。不自行合入主分支或推送远端。

## 首批任务

1. 在本文件的“最新交接详情”提出共享采样所需字段、坐标约定、校准与追踪失效语义，交主控冻结；准备工作可立即进行。
2. Unity 基线和契约确认后，实现键盘驱动的连续虚拟头手轨迹；按键生成动作，不直接调用伤害、格挡成功、弹反成功或闪避无敌。轨迹不能自动对准敌刀，必须允许失手。
3. 接入与设备能力相符的 PICO 头部与双手柄追踪，通过同一动作和战斗判定；战斗动作不依赖按钮。阈值以真机试玩调整，不假定头显和手柄能准确识别腿部或完整身体。
4. 覆盖左右手切换、重新居中、追踪中断与恢复；中断时结束正在识别的动作，避免恢复后产生误击。

## 验收与边界

- 快乐路径：桌面输入产生连续虚拟轨迹，可进入共享判定并完成一次格挡与反击；PICO 轨迹接入后走相同规则。
- 边界至少覆盖：快挥轨迹不因采样丢失；一次挥击只产生一个连续段；无敌人攻击时不会误报成功格挡；手势在错误条件下不会错误释放技能；追踪丢失、恢复和重新居中不会造成突然攻击。
- 同一输入轨迹在不同画面帧率下的结果应在约定容差内；不假设不同平台的 Unity 物理逐帧完全一致。
- 没有真机时只能验证合成轨迹与规则，不能声称 VR 动作识别率、舒适度或手感通过。

## 主控审核（2026-11-08）

**结论：首阶段输入语义通过；冻结以下 v0.1 语义，不等同于代码 API 或真机验收。**

- 桌面合成与 PICO 采样均进入同一按序输入流。采样包含序号、单调的应用观测时间、输入来源、校准代次，以及头、物理左手、物理右手的位置、方向和各自有效性；持刀手另行选择，不交换左右设备身份。没有设备真实采样时间时，不编造或跨时钟域比较。
- 单位为米；会场以玩家初始站立位置的可用地面参考为原点，`+X` 向右、`+Y` 向上、`+Z` 朝会场初始前方。输入侧负责将设备/桌面数据映射到该会场坐标一次；场景与战斗使用同一坐标。地面参考不可用时先提示完成校准，不凭空推断。
- 追踪失效、恢复、重新居中、暂停、重开、换手和缓冲缺口均明确标记为不连续点，不能跨越求速度、扫掠或沿用挥击。不能静默丢弃已采样轨迹；发生缺口时终止相关动作并重新建立基线。
- 头部位置或持刀手位置/方向无效时，战斗模拟与伤害暂停；输入时钟继续，以便接收恢复信息。恢复后待连续有效采样和持刀动作识别就绪，取消中断前招式与挥击，敌人回待机，不强制移动玩家。
- 输入层可输出实时挥击段及技能动作候选；刀刃几何、接触和结果由战斗侧裁定。桌面键盘只产生可失手的虚拟轨迹，VR 战斗不靠按键。技能具体动作和可观察反馈细节与战斗侧对齐后确定。
- QA 的 100 Hz 是**合成夹具**，不是 PICO 实际采样频率。缓存容量、物理步长、跨帧率容差及具体 Unity/PICO API 不在本次盲目冻结，待建立工程并测量后确定；手柄触觉需经主控集成，尚未验证。

首阶段没有代码提交，尚无可合入代码；本线的代码实施被主控的 Unity 基线阻塞。

### 数据交付方式

| 方案 | 优点 | 限制 |
| --- | --- | --- |
| 每次只读最新头手姿态 | 接口简单 | 消费速度低于采样速度时会丢失中间轨迹，不能可靠重建快挥。 |
| **建议：按时间顺序交付已采样的头手姿态** | 战斗可消费每个连续区间；桌面和 PICO 使用同一条判定与回放链路 | 需要明确缓存容量、积压与溢出语义；也不能凭空还原设备没有采到的轨迹。 |

建议保留单一输入样本流，由桌面或 PICO 适配器产生，战斗按顺序消费；不要各自维护桌面和 VR 的战斗成功判定。已采样点正常情况下不静默合并或丢弃；若消费者落后到缓存溢出，必须显式报告缺口，终止受影响的动作并丢弃跨缺口的轨迹连接，从最新有效点重新建立基线。容量、允许积压时长和判定容差由主控与 QA 根据基线测试确定。刀身在连续姿态间的扫掠及接触由战斗侧负责；数据流只能保留应用取得的样本，不保证补回硬件或运行时没有提供的运动。

### 建议的共享数据语义

- 每条样本包含：递增序号、单调时钟上的观测时间（秒）、输入源（桌面/PICO）、校准状态与坐标代次，以及头、左手、右手的数据。相同观测时间以序号确定顺序；暂停、重开或重新居中不能拿暂停前后的点计算速度。具体类型、名字和消费接口由主控定义。
- 每个头/手数据包含位置、方向、**位置与方向各自的追踪有效性**。无效分量不可用于速度、轨迹或接触判断，不能把旧值当作新测量。若运行时提供真实采样时间则可携带并注明其时钟域；否则只能标为应用观测时间，不能假称三设备同时测量、自行编造设备时间，或直接比较不同时钟域的时间。
- 失效、恢复、重新居中、暂停、重开、换手及缓存缺口等不连续信息与采样共用排序，并带原因、影响设备和相关坐标代次；即使暂时没有有效姿态也要可通知消费者。重建基线及识别重新就绪状态需可被战斗侧获知，避免战斗已恢复而玩家挥击仍被抑制。
- 建议统一到主控定义的会场坐标：单位为米，`+Y` 向上、`+X` 向右、`+Z` 为会场初始前方；位置和方向引用同一坐标系。设备追踪坐标到会场坐标的转换只能应用一次，并随校准代次改变；战斗侧按主控定义的会场到 Unity 世界变换消费。地面参考不可用时应标记校准待完成，不推测实际腿部或身体姿态。
- 左右手始终表示物理左、右手；持刀手选择单独表达。切换持刀手时终止旧挥击并让新持刀手重新建立静止基线，不交换设备身份。战斗侧按需要选择有效分量：例如刀具接触需要持刀手位置与方向，头部位移需要头部位置。建议战斗侧基于持刀手姿态及美术提供的握刀点、刀根与刀尖计算刀刃轨迹；输入层不维护另一套武器几何。

### 中断、校准与动作候选

- 检测到设备明确报告追踪无效时立即发布失效，终止该设备正在识别的动作；恢复、重新居中、校准变换、暂停/恢复、重开和样本缺口均是轨迹不连续点。不能跨不连续点连线、求速度或沿用挥击编号。若没有设备采样时间，姿态数值不变可能是用户静止，不能仅凭数值不变判定丢失；设备失效/数据断流的可检测性须以所选运行时能力为准。
- 恢复或重新校准后先建立新基线，持刀手达到约定静止条件后重新允许挥击识别，避免位置跳变或恢复时仍在移动产生误击；静止阈值和持续时间须通过测试确定。重新居中仅由用户或系统明确触发，更新追踪到会场的映射并公布新代次，不强制改变真实头手姿态。
- 如战斗侧需要挥击标识，输入侧只报告动作**候选**：挥击开始后即时输出带同一编号的连续轨迹，结束或中断时结束该编号；不等挥完才交付。输入侧不宣布命中、成功格挡、弹反、闪避、无敌或技能生效；技能手势的具体形态和触发条件未确定前不预设。无有效头部/手部几何数据时，战斗侧不得用旧轨迹推断结果；是否暂停战斗由主控决定。
- 桌面按键生成可随时间采样的虚拟头手轨迹，并记录按键事件和时间，不能直接调用战斗结果。轨迹方向和范围由玩家输入与预设决定，不读取敌人或自动对准敌刀，允许格挡落空。固定轨迹按同一时间轴重采样，不能只依赖渲染帧数；实际键盘事件采集能力以主控选择的输入方案为准。
