## 项目与目标

项目仓库：`/Users/yupeng/projects/personal/pico-wuxia-arena`。

制作一段中式 PVE VR 单挑 Demo，先在 Windows/macOS 用键盘模拟，再适配 PICO 4。真实 VR 的挥刀、格挡、弹反、闪避、技能和处决依靠头部与手柄动作，不以战斗按键触发。桌面和 PICO 共用同一条动作与战斗判定路径。

## 职责边界

- 负责 `Assets/Game/Input/` 与 `Assets/Tests/EditMode/Input/`：键盘生成虚拟头手轨迹、PICO 头显和双手柄轨迹、追踪有效性、校准、重置和与战斗无关的动作候选；负责自己的单元测试。
- 主控拥有共享输入契约与坐标体系。输入层提供带时间戳、追踪状态和校准信息的头手采样；战斗侧结合敌人状态、刀刃接触、攻击范围与时机裁定格挡、弹反、闪避、伤害、技能生效和处决。
- 首版只在需要时提供实时挥刀段和技能手势候选；挥刀过程中即时提供轨迹及挥击标识，不得等动作结束才反馈。闪避成功由战斗系统依据头部轨迹和攻击范围裁定。
- 不修改战斗、美术、主场景、项目设置、依赖和其他 Agent 的进度文档；不覆盖或回滚他人工作。不自行合入主分支或推送远端。

## 验收与边界

- 快乐路径：桌面输入产生连续虚拟轨迹，可进入共享判定并完成一次格挡与反击；PICO 轨迹接入后走相同规则。
- 边界至少覆盖：快挥轨迹不因采样丢失；一次挥击只产生一个连续段；无敌人攻击时不会误报成功格挡；手势在错误条件下不会错误释放技能；追踪丢失、恢复和重新居中不会造成突然攻击。
- 同一输入轨迹在不同画面帧率下的结果应在约定容差内；不假设不同平台的 Unity 物理逐帧完全一致。
- 没有真机时只能验证合成轨迹与规则，不能声称 VR 动作识别率、舒适度或手感通过。

## 主控审核（2026-11-08）

**结论：首阶段输入语义通过；冻结以下 v0.1 语义，不等同于代码 API 或真机验收。**

- 桌面合成与 PICO 采样均进入同一按序输入流。采样包含序号、单调的应用观测时间、输入来源、校准代次，以及头、物理左手、物理右手的位置、方向和各自有效性；持刀手另行选择，不交换左右设备身份。没有设备真实采样时间时，不编造或跨时钟域比较。
- 单位为米；会场以玩家初始站立位置的可用地面参考为原点，`+X` 向右、`+Y` 向上、`+Z` 朝会场初始前方。输入侧负责将设备/桌面数据映射到该会场坐标一次；场景与战斗使用同一坐标。地面参考不可用时先提示完成校准，不凭空推断。
- 追踪失效、恢复、重新居中、暂停、重开、换手和缓冲缺口均明确标记为不连续点，不能跨越求速度、扫掠或沿用挥击。不能静默丢弃已采样轨迹；发生缺口时终止相关动作并重新建立基线。
- 头部位置或持刀手位置/方向无效时，战斗模拟与伤害暂停；输入时钟继续，以便接收恢复信息。恢复后待连续有效采样和持刀动作识别就绪，取消中断前招式与挥击，敌人回待机，不强制移动玩家。

### 坐标、按键和连续运动

以下在已校准的桌面会场内描述：地面初始原点 `(0,0,0)`、米为单位，`+X` 向右、`+Y` 向上、`+Z` 朝会场前方。桌面虚拟头、左手、右手初值分别为 `(0,1.60,0)`、`(-0.20,1.25,0.35)`、`R0=(0.25,1.25,0.35)`，方向均为 `Q0=(0,0,0,1)`；四元数顺序 `(x,y,z,w)`。这是合成身高和姿态，不推断 PICO 用户的真实身高。下表相对玩家移动根节点，整组沿地面平移；头部探身只改变头部。

| 操作 | 按下 | 保持与释放 |
| --- | --- | --- |
| `W/A/S/D` | 沿会场前/左/后/右启动平移。 | 头与双手一起按 `0.60 m/s` 连续移动；对角线归一化为同速，相反方向抵消。释放即停在当前位置，不自动回位；`A/D` 可用于实际侧移。 |
| `Q/E` | 头部向左/右探身，双手不跟随探身。 | 以 `0.50 m/s` 到相对根节点的 `-0.25/+0.25 m` 上限；两键同时按下以零为目标。释放后以相同速度回到根节点上方。只产生头部轨迹，不授予闪避或无敌。 |
| `J/K/L` | 分别选择左、上、右持刀姿势；从当前手位到目标的时间取 `max(0.20 s, 位移距离 / 1.50 m/s)`，方向同步插值。新选择清除手动偏移。 | 按住不重复；释放不回位。姿势过渡途中再次选择时从当前姿态转向新目标，不读取敌人或敌刀。多键连续按下以最近一次按下为准；同一时间的事件按 `J→K→L` 排序。 |
| `←/→/↑/↓` | 手动向左/右/前/后微调持刀手。 | 姿势移动完成后按 `0.50 m/s` 平移，斜向归一化；会场相对根节点的 `x` 限于 `[-0.90,0.90]`、`z` 限于 `[0.20,0.90]`，高度不变。释放后停住，允许故意错开刀路。 |
| `Space` | 仅在已选姿势已到位、手部有效且动作识别已就绪时，启动一条 `0.25 s` 的虚拟挥刀轨迹。 | 松开不截断正在生成的轨迹；按住不连发。到达终点后停住，不自动回刀；必须松开、手部重新就绪后再按，才开始相反方向的下一次运动。忙碌时的按下不排队。 |
| `F` | 手部有效且空闲时启动下述双手技能**候选姿态**，不是直接释放技能。 | 保持推进姿态并在近距停住；释放后从当前姿态平滑回到开始前的双手位置。未完成的动作是否构成候选只看实际轨迹和共享识别规则。 |
| `H` / `C` | `H` 切换物理持刀手；`C` 明确请求桌面重新居中。 | 均只响应按下沿；终止当前动作并标记不连续。换手不交换或瞬移左右手，须重新选择姿势；居中重建桌面初始姿态及校准代次。两者均须重新建立基线和就绪状态。 |
| `T` / `Y`（桌面测试入口） | 分别切换当前持刀手追踪有效性、头部位置追踪有效性，用于复现失效与恢复。 | 只响应按下沿，不用于 VR 战斗。具体入口须主控接入；测试注入的位置跳变不能冒充设备实测。 |

### 技能候选：待战斗侧确认的手势提案

为满足桌面端到端准备，建议 `F` 按住时，双手先从当前姿态移至 `(-0.35,1.30,0.50)`、`(0.35,1.30,0.50)`，保持 `0.10 s`；再在 `0.30 s` 内靠拢至 `(-0.12,1.30,0.50)`、`(0.12,1.30,0.50)` 并保持，方向维持开始时各自方向。张开及释放后的回位均从当前姿态开始，时间取 `max(0.30 s, 较远一只手的位移 / 1.50 m/s)`，双手同时到达，不瞬移。从下方初始姿态张开恰用 `0.30 s`；其他起点可能更慢。

可由**桌面和 PICO 共用**的识别器考虑：双手位置有效，先分开至少 `0.35 m` 持续 `0.10 s` 进入准备；从距离小于 `0.35 m` 起，须在 `0.60 s` 内靠拢至不超过 `0.25 m`，并连续保持 `0.20 s`，才发出一次带唯一标识和时间的候选。期间超时或任一必需位置失效则取消准备。产生候选后，双手分离至大于 `0.25 m` 时结束该候选；失效或不连续时取消，重新触发须再次分开并满足准备条件。候选只描述观察到的双手动作，不等于消耗资源或技能生效。上述阈值、手势形态、与挥击识别的冲突以及战斗生效条件均须主控与战斗侧审核后才能冻结；不在桌面端以按键直接发候选来绕过共同识别。

### 共享接口必须承载的语义与边界

1. **样本和时钟：** 序号、单调应用观测时间、输入来源、校准状态及代次；头、物理左手、物理右手各自位置、方向以及位置/方向有效性；单独提供持刀手选择。没有设备真实采样时间时不能编造；若有其他时钟域，要明确来源，不能直接与应用时间混比。
2. **不连续信息：** 追踪失效/恢复、暂停/恢复、换手、重新居中、重开及缓存缺口，必须与采样有明确顺序、时间和影响部位，及时通知战斗；取消旧动作，禁止跨点连线、计算速度或扫掠。缓存溢出不可静默丢点，重新建立基线；具体容量和背压方式待工程测量。
3. **动作状态：** 共享识别器从样本实时产生挥击候选的开始、连续更新、结束或中断及同一挥击标识，并提供恢复后就绪状态；一次连续挥击不得因多帧分成多个标识，也不能跨不连续点沿用标识。候选须能边运动边消费，不等待动作结束。技能候选在规则确认后也须暴露唯一标识、产生时间、结束或取消，使 QA 能核对不重复生效。
4. **职责和恢复：** 手柄轨迹不附带命中、格挡、弹反、闪避或技能成功；战斗负责刀刃、攻击区域、时机与结果。头部位置或持刀手位置/方向无效即暂停战斗，输入时钟不暂停；待连续有效与识别就绪，再取消旧招、回到待机。不能把旧值、恢复跳变或暂停期间的模拟时间当成有效轨迹。
5. **采样限制：** 合成夹具可在相邻关键点按 `100 Hz` 重采样，保持段不提前插值；运行时必须有序交付已获得的采样，不能凭插值宣称取得设备未提供的点。键盘事件时间、源时钟精度、帧率容差和 PICO 实际可用追踪能力待运行时验证。
