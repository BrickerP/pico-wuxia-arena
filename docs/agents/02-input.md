# 输入与桌面轨迹交付

## 当前范围与职责

设备输入与桌面预演共用 `TrackingEventBuffer → TrackingState → ArenaSession → PlayerCombatResolver`。主控统一集成、编译与后续设备操作，协作者交付后结束，当前不启动等待循环。

技术栈为Kotlin + PICO Spatial SDK6.1.9，Space Pro／OS6，桌面入口为PICO模拟器。

## 上一轮产出

已有SDK头手观察、continuity／coordinateEpoch、暂停与重开控制，以及HMD派生固定手位预演。上一轮W已产生头手观察并进入出招资格查询，独立挥刀与胜负仍未接通。历史测试与日志不能证明本轮新输入效果。

## 本轮 review 修正与代码交付

- `DesktopCombatInput`生成斩击、前刺、架刀、侧闪、下蹲及双手蓄推的连续头手轨迹。
- 模拟器debug条件下，Activity正常按键入口和五个预演动作按钮触发轨迹。按钮不直接扣血，最终结果由同一个姿态判定器产生。
- `PicoTrackingAdapter`保留原始HMD样本，`TrackingSession.onFrame`在排空前统一推进预演配对，静止HMD也能完成动作。
- 手位与动作随HMD朝向变换，合成来源为DESKTOP，质量保持UNKNOWN。设备路径继续使用实际SDK观察。
- 暂停、重开、停止与追踪中断清掉宏和旧动作基线，既有生命周期handle失效及控制队列语义继续承担控制入口。
- 破势与处决合并为G及相同双手蓄推手势，敌人低血自动处决，独立F入口已经移除。

| 键位 | 动作 |
| --- | --- |
| 1 / J，2，3 | 斩击、左斩、右斩 |
| 4 / K | 前刺 |
| 5 / V，6 / B，7 / N | 上架刀、左架刀、右架刀 |
| 8 / Z，9 / X | 左闪、右闪 |
| C | 下蹲 |
| G | 破势 / 处决 |

WASD、Q/E和右键保留宿主相机操作。实际VR战斗使用头手动作，预演区仅在桌面模式显示。

## 下一步交付条件

主题review要求设备正常交战时优先显示“连胜三场 · 读招、架刀、反击”。桌面预演和追踪异常继续呈现真实来源与就绪状态，VR格挡、弹反和闪避沿真实头手动作识别。

按用户要求，本轮未做按键、模拟器或设备自测。后续围绕动作意图与实际轨迹的一致性核对键盘、预演按钮、设备动作、暂停恢复、新session与重开，确认同一输入不会跨代次重复命中。UNKNOWN表示当前软件观察来源的质量语义，真机追踪有效性仍需验收。
