# 酒馆试炼 · 浏览器代理原型 v0.13

规则标识 `wuxia-contact-v0.13 / silk-rack-4`。

这是**单文件网页代理原型**，用来在桌面浏览器上快速验证动作衔接、兵器架、精度 HUD 和跑跳输入语义，不是 PICO 端 APK，也没有替代 `app/` 下的 Kotlin + Spatial SDK 工程。

## 怎么跑

1. 用桌面 Chrome / Edge 打开 `index.html`（需要联网，角色、刀和酒馆 GLB 走固定提交的 jsDelivr CDN）。
2. 点「先试木桩」。D 走向右侧兵器架，指向近处武器握点标签，用左／右鼠标键取到对应手；刀、剑、枪、棍间隔 0.95 m，只取一把，新取旧物归架。
3. 回中央木桩：短上劈、下刺、左右砍；重复刺推进变式 0/1/2；释放 65% 后可预缓存一条 550 ms 输入，收势 90 ms 后接下一招。
4. 移动：WASD，双击 W 进入短跑，冲刺结束有气力代价；双握（左右键同时按住）上提为跳跃代理，红光末段双握前送为反投。

## 输入是代理，不是 VR

- 键盘只有 WASD；鼠标左右键只代理双手握持／拾取，不承担攻击点击。
- 头显里的真实 6DoF 追踪、跑步姿势识别和跳跃识别尚未接线；本原型的「双击 W 跑」「双握上提跳」只是语义占位，用来先确认节奏和代价是否成立。
- 松按钮仍持物是本网页的妥协，正式 VR 应改为保持握持。

## 明确没有验证的

- 完整三轮通关、小径全程、护手受阻新模型仍未跑通；契约内 `J-TRIAL` / `J-TRIP` / `J-GRIP` 为 `not_run`。
- 全部实测来自可信 CDP 鼠标／键盘与只读状态采样，时间取模拟时间，不是渲染帧，也不是真人成功率。
- 动画槽 `clip` 全为空，等待外部动作素材；不构成成品动作。
- 真机帧率、舒适度、6DoF 与 PICO 追踪性能均未验证。

## 与 Kotlin 主线的关系

`app/` 的集成版仍是当前 PICO 交付候选；本目录只用于提前验证手感假设。任何进入真机的结论都必须回到 Kotlin 工程重新接线并实测，不能把这里的数值直接搬过去。
