# 动作、双手、兵器架与VR跑跳接口 v0.13

规则集 `wuxia-contact-v0.13 / silk-rack-4`。基于原单HTML迭代，VR优先；本地不提交GitHub，未修改Kotlin、未构建APK。`motion-core.js`与`battle-core.js`是独立纯JS源码，HTML由锚定打包内嵌；默认DOM/模型/加载/调参仍在HTML，不宣称完整引擎插件化。

## 双手输入

- VR设计不把左手锁为攻击、右手锁为防御。握持哪只手，哪只手可攻防；另手辅助持握、合抱反投。当前网页只呈现一把主武器，**不支持双持两把武器各自自由扫掠**。
- 鼠标左右键仅代理左/右抓握与拾取：走近右侧兵器架（四种武器间隔0.95m），水平距离1.6m内指向握点，按相应键拾取。松键不丢刀；新取武器将旧物归原架位。空手期间敌人等待，取武器后开始当前战斗倒计时；不是正式战斗无敌能力。
- 方向攻击规则不变；新手势在释放65%后可预缓存一条550ms意图，收势90ms后接下一招，链接起手120ms从当前刀姿直连目标起手，不重走中立撤刀。每招释放仍刀/剑300ms、枪340ms、棍360ms，不继续加快挥刀。起手或收势匹配白蓝来刀可取消该招并转守；释放仍承诺，不瞬间掉头。刀刀受阻清队列、消费当招，与旧接触规则一致。最终纯规则模型/DOM仍在HTML内接线，不能只替换模块就算完整架构解耦。
- 单指针攻击仍短上劈/下刺/左右砍；慢移或匹配白蓝方向摆刀，停止操作0.6s回到中立以允许精度恢复。左右持握镜像、刃长/宽/厚/伤害/压力/时长变化已实现。枪只有尖端28cm的身体/木桩伤害，杆仍可碰刃；棍钝击不要求刃向。
- 双键抓握时短下划代理前送合抱，仅在投技前摇末380ms或释放前140ms有效、距离<1.8m、玩家未破防、敌攻击未结算且无动画槽占用；提前保持双键不自动反投。鼠标代理只是单点合成，不是双控制器轨迹取证。

```js
// PICO适配层提供头部相对坐标：x向右，y向上，z向后，米；t以秒单调递增。
window.wuxiaModules.sampleVRHands(
  {tracked:true,grip:true,position:[-.35,1.2,-.10]},
  {tracked:true,grip:true,position:[ .35,1.2,-.10]},
  timestamp
);
```

真正双手识别独立`createHugRecognizer`：550ms内双手间距缩小至少12cm、平均前送至少16cm，最终横向间距10–55cm，高度85–175cm。缺追踪、松握、非法坐标重建；保持终点姿势不触发。**这些是待真机校准初值，非PICO已接线**。当前接口仅接反投意图，普通双手攻防仍未接正式SDK。

## 武器与Boss

`WuxiaBattleCore.weapons`含刀0.84m、剑0.94m、枪1.65m、棍1.35m；基础伤害13/12/15/10、压力16/14/20/28。动作标称总时长0.80/0.76/0.96/1.01s。程序剑枪棍为占位几何，刀用原GLB；不是正式武器资产。枪刺起手撤杆防止长武器未前送就触体。

三Boss复用现有GLB，均匀体型0.96/1.10/1.26，身体/头碰撞尺度同步，**没有三个独立造型**。剑客HP180精度72硬度0.9、化劲压力×1.6；枪卫HP235精度100硬度1.25、收势命中压力×1.8；巨擂HP300精度140硬度1.8、棍压力×2。不同序列见配置；Boss目前仍持原刀，枪卫名称不代表已持完整长枪动作。

霸体只在敌prepare/release且动作压力小于18（枪卫）/30（巨擂）时抗轻击取消；照常承伤、耗精度、局部停刀，精度空条覆盖霸体。玩家攻击起手/释放未破防时可承受一次普通身体受击而保留动作，照常扣血及22精度；投技不受玩家攻击霸体抵消。所有配置是原型设计初值，非已平衡。

## 精度裁决

敌我独立条，玩家100。普通实体格挡花18，精准化劲花5，普通受击花22，抓中花30；体力耗空额外花18精度并补12体力，不再另造独立破防状态。敌方身体有效命中或自身武器挡住攻击、被化劲/反投消耗精度，普通挡住敌刀不白送敌压力。

敌压力=四舍五入(基础压力×适用弱点倍率/硬度)，下限1。化劲基础24、反投42；长枪非刺压力×0.65，剑刺×1.25。巨擂棍28×2/1.8=31，对比刀16/1.8=9；剑客刀化劲24×1.6/0.9=43，两次72→29→0。

停止移动（速度<0.04m/s）、无攻击/守势/动画、停止动作超过0.6s后每秒恢复16；持握按钮本身不阻止恢复。网页守势0.6s无新动作回中立，真实VR应按实际手部静止/中立判定。玩家空条破防1.1s禁攻防/反投，允许步行撤开；敌空条破防2.2s有处决机会。恢复时先补最大值55%，再按静止条件恢复；破防内追加冲击不延长控制、无无限控。首次空条事件一次性触发。

## 反应时间

有限脉冲而非整局慢速：白0.65倍300ms、蓝0.45倍320ms、红0.40倍650ms，每个敌攻击/颜色只触发一次；可关。当前只减慢**敌方攻击与动作更新**，玩家控刀、WASD、资源及反投时钟实时，头部相机不被慢放/翻滚；是辅助反应时间，不是全世界时间缩放。真机头追踪不可进入慢时钟。暂停停主循环、清抓握和当前脉冲，恢复不重新触发同一颜色；重开清脉冲历史。

## 空动画槽（由用户另做素材）

`boss_grab / counter_grab / execute`三槽，`clip:null`，占位时长1.05/1.05/1.25s；仅锁战斗接触和输入、防重复动作，不移动头部，不制作抓摔动作。伤害/反投压力/处决HP0在玩法裁决时一次性提交，不由动画回调或可重复marker改血。

```js
// 游戏暂停且没有活动动画槽时安装，禁止动画直接写战斗状态。
window.wuxiaModules.attachAnimation({
  begin(slot) {
    // slot.token/id/started/until/context{attack,boss,weapon,hand}/assetMissing
    // 用id选用户制作的合法动画；仅摆角色、虚拟手与武器，不接管真实头部相机。
  },
  end(slot) { /* 释放动画角色占用；可选 */ },
  cancel(slot, reason) { /* pause/restart/terminal，停止动画并还原 */ }
});
```

支持互斥/自然结束/暂停取消/重开取消/终局清理，适配器异常不改结果。当前时长由空槽固定配置，生产接入需把角色根、手/武器attach点、事件marker、相机策略、取消/恢复姿态共同标定。marker名称只列契约，尚未做完整动态时长/marker回执接口。处决需要敌破防、2.2s内、距离≤当前武器长+0.85、新攻击意图；不会空精度自动斩杀，不允许画面回调重复送伤害。

## 跑跳与PICO接入边界

`locomotion-core.js`是独立纯输入分类与数值配置，不依赖Three/DOM。第三个锚定包内嵌HTML；无PICO SDK依赖、未编译原Kotlin工程。普通步行前2.05/后1.35/侧1.65m/s、加速度4.8m/s²；敌追步1.65/退1.0/侧0.95m/s。网页双击W间隔≤300ms，在持续W期间跑3.15m/s；松W、动作/守势/动画或气力≤8降回步行。跑耗14/s，不在跑中同时回气。不是全方向冲刺，不能按Shift/空格攻击或跳。

网页非红抓阶段双键抓握+主动短上提（归一化0.12、550ms内）可触发低幅虚拟跳；在新双握主动上提时放松已有守势，无攻击动作、无槽、未破防、站地、气力≥12、冷却850ms才可跳。虚拟跳初速2.45m/s、重力7.5m/s²，解析峰约0.400m/总0.653s，离散模拟约0.39m；不提供无敌帧，不允许越墙/越人，跳会提高虚拟手、身体碰撞与网页相机高度，无落地头晃/旋转。暂停冻结跳高度与竖速，重开清空。PICO应将虚拟rig偏移与真实追踪头位分开，**不能硬写真实头的姿态**；跳跃视觉垂移仍可能不适，当前不是VR舒适度完成，必须可关闭并真机验证。

```js
window.wuxiaModules.sampleVRLocomotion({
  t: monotonicSeconds,
  left:{tracked:true,position:[-.25,.90,-.20]},
  right:{tracked:true,position:[.25,.90,.10]},
  move:{x:0,y:1}, // 适配层统一为前推正y，不直接套设备轴符号
  stickSprint:false, jumpButton:false
});
```

坐标为校准后的稳定追踪空间：x向右、z向后，y为距地高度（米）。不能把HMD的y相对差直接当距地高度。双手低于1.15m、1秒内至少3次交替前后摆（差幅>0.14m、单样本变化>8mm），且移动意图≥0.65、非攻击/守势/红抓/动画，可选加速；新手势触发保持600ms。双手低位均高<1.05m后450ms内平均上提>0.22m、左右高度差<0.12m、平均高度<1.6m才跳；不需要真人离地，不把HMD跳动当跳。握持姿态不作为脚部运动推断。字段缺失/非有限坐标/追踪间隔>200ms/倒退时间重建，不沿用失追高速；同姿势保持不重复跳，按钮路径检测新按下而非保持。

PICO官方Spatial文档提供左右同帧姿态/按键快照，Full Space、supportState、线程缓存/主线程分发需检查；**项目SDK6.1.9版本兼容未构建验证**。官方没有直接跑跳分类语义；以上阈值是设计初值，需要按身高、坐姿/站姿、持枪等校准。硬件型号/空间能力未知，网页仅验证规则与代理输入。出处 https://developer.picoxr.com/document/spatial-sdk/controller-tracking/ 。

## UI分支接入

当前精度规则仍“满值健康、消耗至0破防”，**不改为只狼的累计满条规则**。HUD展示压力=(1-剩余/最大)，从中心向两侧金条增长；数值仍标剩余精度。敌上方、玩家下方；空条文字区分“近身新招处决”与“我方撤步”。底层可读frame给另一UI分支，默认HUD仍直接写DOM，暂未验证不同UI热替换。

## 只读对外与复现

`window.wuxiaModules.readFrame()` JSON隔离副本，`subscribe()`冻结事件；`listWeapons/listBosses/listPacks`只读目录。`window.wuxiaDemo.readState()`仅读状态用于测试，无改血、瞬移或胜利入口。

```sh
node 模组源码/motion-core.test.js
node 模组源码/battle-core.test.js
node 模组源码/locomotion-core.test.js
node 模组源码/bundle-motion.js
```

打包器只替换三处BEGIN/END核心锚点，不覆盖UI或骨骼适配。完整三轮/小径、四武器全姿态刀杆碰撞、另一模型热替换、左右独立自由控刀、PICO输入/追踪恢复、性能/舒适度没有本版完整验收。
